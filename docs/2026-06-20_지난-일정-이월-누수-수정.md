# 2026-06-20: 이월(carryover) 제거 — "오늘의 할일"만 생성

## 배경

사용자 보고: 아침 todo 알림(haru-bot)에 **오늘 일정과 함께 며칠 전 일정**이 같이 옴.
명세: **캘린더는 KST 오늘 날짜**, **Notion은 오늘 날짜/오늘 요일의 반복 할일**만
"오늘의 할일"이어야 한다.

haru-bot 아침 알림은 자체 수집 없이 notion-daily-todo가 만든 `YYYY-MM-DD TODO`
페이지를 그대로 읽어 보낸다 → 근본 원인은 이 페이지 생성 쪽.

## 진단

- 캘린더 **수집** 단계는 이미 KST 오늘만 가져옴 (6/16 `_event_on_kst_day`).
- **이월(carryover)** 이 원인: 전날 페이지의 미완료 항목을 다음 날로 이월했는데,
  캘린더 일정(`[14:00] 회의`)·요일 반복("화요일마다")처럼 날짜·요일에 매인 항목이
  체크 안 된 채 남으면 그 날 외에는 재생성되지 않아 **매일 계속 이월** →
  "며칠 전 일정"으로 누적됐다.

## 결정

이월 자체를 제거. 매일 페이지는 "오늘의 할일"만 담는다:
템플릿 고정 task + 오늘 KST 캘린더 일정 + 오늘 날짜/요일 반복 할 일.

(전날 못한 일을 가져오는 동작이 필요하면, 자동 이월 대신 사용자가 "내일로 미룰 것"을
선택하는 인터랙션으로 별도 설계 — 추후 검토.)

# (추가) 경민 일정 제외 + '내일로 미루기' 선택적 이월

## 1. 경민 일정 제외 (Claude 판단)

요청: 캘린더의 '경민' 일정(본인 할 일 아님)은 기록하지 말 것. 단 하드코딩 키워드
매칭이 아니라 **Claude가 맥락으로 판단**.

- `filter_others_calendar(events, today)` 추가 — 수집된 캘린더 일정을 분류 전에
  Claude(`claude-sonnet-4-6`, json_schema `{keep:[index]}`)에게 보내,
  `EXCLUDE_PERSON="경민"`이 주체/대상인 일정(약속·레슨·모임·수업·인터뷰·픽업 등)을
  제외하고 본인 일정 index만 keep. 애매하면 keep. API 키 없거나 실패 시 전체 유지.
- `main`: `calendar_events = filter_others_calendar(collect_calendar(now), now)`.
- 검증: 샘플 7건 중 경민 4건 제외, 본인 3건(프로모션코드/만두/이자날) 유지.

## 2. '내일로 미루기' 선택적 이월

자동 이월은 제거됐지만, 사용자가 저녁에 **직접 고른** 항목만 다음날로 넘기는 채널.
별도 페이지/환경변수 없이 daily 페이지를 공유 저장소로 사용:

- haru-bot webhook이 저녁 '완료' 직후 "내일로 미룰 항목" 키보드를 띄우고, 고른 항목을
  그날 `{date} TODO` 페이지의 `🔜 내일로` 섹션(heading_2)에 to_do로 append.
- notion-daily-todo: `collect_deferred_from_yesterday(yesterday)` 추가 — 전날 페이지에서
  `내일로` heading 이하 to_do 텍스트만 수집. `find_page_by_title()` 헬퍼 추가.
- `main`: 수집한 항목을 `recurring`에 `{"section":"내일로","task":t}`로 합류 →
  Claude가 일/생활/공부로 재분류, must-include 보장, build_page에서 중복 dedup.
- 각 날의 `🔜 내일로` 섹션은 그 저녁 고른 것만 담으므로 누적·재이월 없음.

## 카테고리 일/생활/공부 전환

분류 가이드를 일/생활/공부로 변경했고, 템플릿 페이지 heading도 API로 업무→일,
개인→생활, 공부→공부 변경(2026-06-20). 실제 카테고리는 템플릿 heading에서 나옴.
