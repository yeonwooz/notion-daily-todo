# 2026-05-05: 월별 sub-page 분리 + 연도 자동 처리

## 배경

기존 구조는 매일 `YYYY-MM-DD TODO` 페이지가 `2026 할일` 페이지(=PARENT_PAGE_ID)
직속으로 쌓여서 `# 날짜별 할 일` 섹션이 끝없이 길어짐(~70개). 또 매년 12월에
사용자가 `{year+1} 할일` 페이지를 직접 만들고 GitHub secret을 갱신해야 했음.

## 새 구조

```
ROOT_PAGE_ID ("할일")
└── {YYYY} 할일                   (ensure_year_page가 매년 1/1 자동 생성)
      ├── # 할 일                 (사용자가 채우는 yearly 반복 패턴)
      ├── YYYY-MM                 (ensure_month_page가 매월 1일 자동 생성)
      │     └── YYYY-MM-DD TODO   (매일 페이지)
```

## 변경

### `create_daily_todo.py`

- **`get_blocks` paginated** — 기존엔 page_size=100 한 번만 호출해서 child가
  100개 넘는 페이지(우리 PARENT처럼)는 끝부분이 잘렸음. cursor 처리 추가.
- **환경변수 `PARENT_PAGE_ID` → `ROOT_PAGE_ID`** — 매년 새 연도 페이지를 자동
  생성할 수 있도록 상위 "할일" 페이지를 가리킴.
- **`ensure_year_page(year, root_id)` 신규** — ROOT 안에서 `{year} 할일` 페이지
  찾고, 없으면 자동 생성. 1/1 첫 실행 시 자동으로 새 연도 페이지가 생김.
  (단 `# 할 일` yearly 반복 패턴은 자동 복사하지 않으므로 사용자가 직접 채워야
  매일 페이지에 반복 task가 들어감.)
- **`ensure_month_page(year_month, parent_id, existing)`** — parent_id 매개변수
  추가. year_page 안에서 월 sub-page 확보.
- **`collect_existing_month_pages(parent_id)`** — parent_id 매개변수 추가.
- **`build_page(today, parent_page_id, ...)`** — parent를 매개변수로.
- **`main()` 흐름**:
  1. `ensure_year_page(current_year)` — 연도 페이지 확보
  2. `ensure_month_page(current_month, year_page_id)` — 월 sub-page 확보
  3. `parse_recurring_todos(get_blocks(year_page_id))` — yearly 반복 패턴
  4. 매일 페이지를 월 sub-page 안에 생성

### `.github/workflows/daily-todo.yml`

- `PARENT_PAGE_ID` → `ROOT_PAGE_ID` (secret도 갱신)
- 사용 안 하던 `YEARLY_TODO_PAGE_ID` env 라인 제거

## 일회성 마이그레이션 (이미 완료)

지난 70개의 PARENT 직속 매일 페이지(2/22~5/5)를 월별 sub-page로 옮김.

- Notion API의 `PATCH /pages with parent`는 **응답은 200이지만 실제 parent를
  바꾸지 않음** (검증 결과). 그래서 "콘텐츠 복사 + 원본 in_trash" 방식 사용:
  1. 새 페이지를 월 sub-page 안에 같은 제목·콘텐츠로 생성
  2. 원본 페이지 in_trash 처리
- 페이지 URL은 변경되지만 댓글/외부 참조 의존이 없어 수용 가능.
- 해당 마이그레이션 코드(`archive_legacy_daily_pages`, `_clone_block_for_create`,
  `DAILY_PAGE_PATTERN`)는 1회용이라 작업 후 제거함.
