# 2026-06-13: 캘린더/반복 항목 LLM 분류 누락 회수

## 배경

사용자 보고: 캘린더에 있는 일정이 매일 TODO 페이지에 안 잡히는 경우가 있음.

원인 분석:
- `classify_items`가 `recurring + calendar_events + urgent_pool`을 한 번에 LLM에 보내 분류
- 프롬프트 규칙에 "빠른시일 풀에서는 1-2개만 선별"이 있어, LLM이 캘린더/반복 항목에도 동일한 선택권을 행사해 일부를 드롭
- JSON schema(`CLASSIFY_SCHEMA`)는 `{category, items}` 배열만 강제하고 입력 항목 누락을 검증 안 함

## 변경 (`create_daily_todo.py`)

### 1. `classify_items` 프롬프트 강화

규칙 첫 줄에 명시:

```
- [오늘의 캘린더 일정]과 [반복 할 일]의 모든 항목은 빠짐없이 분류 (드롭 금지)
- "1-2개만 선별"은 오직 [빠른 시일 내 처리할 일들]에만 적용
```

캘린더 라벨 표기에 `[종일]`도 추가 (기존엔 `[HH:MM]`만 언급).

### 2. 누락 회수용 2차 LLM 호출 — `_recover_missing_items`

1차 분류 결과를 받은 뒤:

```python
must_include = [e["label"] for e in calendar_events] + [it["task"] for it in recurring]
missing = [m for m in must_include if m not in included]
if missing:
    recovered = _recover_missing_items(client, categories, missing, today)
    # result에 머지
```

- 누락된 항목만 따로 모아 두번째 LLM 호출로 카테고리만 분류 (단순 polyfill로 첫 카테고리에 박지 않고 LLM 판단 사용 — `[[feedback_llm_over_keyword_rules]]` 규칙 따름)
- 2차 호출 실패하거나 2차도 일부 누락하면 그제서야 첫 카테고리로 폴백 (절대 사라지지 않도록 보장)
- 응답에 입력 외 텍스트가 섞이면 무시 (입력의 부분집합만 채택)

### 적용 안 한 항목

- `urgent_pool`은 의도적으로 1-2개만 선별하는 동작이므로 누락 회수 대상에서 제외
- 캘린더 수집 자체(iCloud CalDAV) 문제는 별도 — `[Calendar] N개 일정 수집` 로그가 0이면 그쪽 디버그 필요

## 흐름

```
classify_items(categories, recurring, calendar_events, urgent_pool, today)
  ├─ 1차 LLM 호출 (전체 분류)
  ├─ must_include = calendar_events.label + recurring.task
  ├─ missing 검사
  └─ if missing:
        _recover_missing_items(client, categories, missing, today)
          ├─ 2차 LLM 호출 (분류만, 모든 항목 포함 강제)
          ├─ 응답 외 항목은 입력의 부분집합만 채택
          └─ 2차도 누락 시 categories[0]으로 폴백
```
