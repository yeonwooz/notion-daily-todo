# 2026-06-14: 캘린더 일정 무음 누락 수정 (vobject 의존성)

## 배경

사용자 보고: 오늘 아침 TODO에 캘린더 일정이 또 안 잡힘. 어제(`2026-06-13`)
LLM 분류 누락 회수를 넣었는데도 여전함.

진단(GitHub Actions 로그 + 로컬 재현):
- Actions 로그가 매일 `[Calendar] 0개 일정 수집` (6/9~6/14 전부) — 에러 없이 0건
- 즉 LLM 분류 단계가 아니라 **캘린더 수집 자체가 0건**이었음
  (어제 doc 44번 줄에서 이미 "0이면 별도 디버그 필요"로 예고됨)
- 로컬 재현 시 iCloud 연결·검색은 정상 (오늘 `중요` 4건, `💕` 4건 실제 존재)
- 파싱 단계에서 전부 실패:
  ```
  CRITICAL: vobject library is not installed (vobject is no longer an official dependency in 2.0)
  AttributeError: 'NoneType' object has no attribute 'vevent'
  ```

## 근본 원인

1. `requirements.txt`가 `caldav>=1.3.9`로 열려 있어 러너가 **caldav 3.2.0** 설치
2. caldav는 **2.0부터 `vobject`를 의존성에서 제거**
3. 코드는 구 API `ev.vobject_instance.vevent` 사용 → vobject 미설치 시
   `vobject_instance`가 `None` 반환 → `AttributeError`
4. 해당 코드가 `try/except Exception: continue` 안 → **모든 일정이 조용히 스킵**,
   에러 로그도 안 남음 → `[Calendar] 0개`

→ 어제 넣은 LLM 누락 회수는 입력이 0건이라 작동할 여지가 없었음.

## 변경

### `create_daily_todo.py` — `collect_calendar`

- `ev.vobject_instance.vevent` → `ev.icalendar_component` (caldav 2.0+ 표준)
  - `summary = str(comp.get("summary", "제목 없음"))`
  - `dtstart = comp.get("dtstart").dt` (datetime → `[HH:MM]`, date → `[종일]`)
- `cal.name`(deprecated) → `cal.get_display_name()`
- 파싱 실패를 조용히 삼키지 않고 `[Calendar] '<cal>' 일정 파싱 실패: ...` 로그 출력
  (같은 류의 무음 실패 재발 방지)

### `requirements.txt`

- `caldav>=1.3.9` → `caldav>=2.0` (icalendar 기반 API 보장)
